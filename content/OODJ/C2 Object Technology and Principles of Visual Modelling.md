# Object Technology
## What is Object Technology?
> Set of principles (abstraction, encapsulation, polymorphism) guiding software construction, together with languages, databases and other tools that support those technology. 
> —*Object Technology - A Manager's Guide*, 1997
## Strengths
- reflects a single paradigm
- facilitates architectural and code reuse
- reflects real world models more closely
- encourages stability
- adaptive to change
## Where is it Used?
- **Client/Server Systems** and **Web Development**
  Object technology allows companies to encapsulate business information in objects and helps to distribute processing across the Internet or a network.
- **Real-time Systems**
  enables real-time systems to be developed with higher quality & flexibility
- **Object-Orientation**
	- melds the data & data flow process together early on in the lifecycle
	- high level of encapsulation
	- promotes reuse of code differently
	- permits more software extensibility
# Principles of Visual Modelling
## What is a Model?
Simplification of Reality.
## Why Model?
- helps visualise the system
- allows us to specify the structure or behaviour of the system
- gives us a template that guides in constructing the system
- documents the decisions made
- better understand the system we're developing
- we cannot comprehend the system in its entirety otherwise

Modeling becomes more *important* as the project becomes more *complex*.
### Software Teams Often Don't Model
Many software teams:
- start coding from project requirements
- work longer hours and create more code
- lack any planned architecture
- are doomed to fail

Hence, modeling is a common thread when it comes to successful projects.
## Model-Driven Architecture (MDA)
An **approach** to using models in software development.
- *separate* the system's specifications from the details of how the system utilises platform capabilities
- specifying platforms
- choose a particular platform for the system
- transforming the system specification into one for a particular platform
## Four Principles of Modeling
1. The model influences *how* the problem is attacked.
2. Every model can be expressed at different levels of *precision*.
	- the best kinds of models let you *choose* the degree of detail depending on:
		1. who's viewing the model
		2. why they need to view it
3. The best models are connected to reality.
	- a good model reflects potentially **fatal** characteristics
4. No *single* model is sufficient.
	- create models that can be built & studied separately but are still interrelated
